AUTISMLENS
----------

Full title:
"AutismLens: A Multimodal AI System for Manual-Grounded Interpretation of Autism Screening Assessments"

Type:
Final Year Project (FYP) — Project Proposal, submitted 07 August 2026.

Supervisor:
Dr. Faryal Nosheen

Team:
- Talha Rehman (01-136232-048)
- Abdul Rehman (01-136232-052)

Department / University:
Department of Computer Science, Bahria University, Islamabad.

Objective (per proposal):
To design and develop a multimodal intake system (structured form, PDF, and image) that extracts item-level scores from psychological evaluation sheets and generates a manual-grounded interpretive report using LLM embeddings and retrieval-augmented generation matched against a licensed scoring manual.

Problem being addressed:
Standardized autism screening instruments (e.g., Vineland-3) capture rich item-level behavioral data, but manually cross-referencing marked evaluation sheets against a printed scoring manual is slow, inconsistent across staff experience levels, and prone to transcription error — especially in under-resourced clinics/schools that lack a specialist readily available to interpret results promptly.

System architecture — 5-layer pipeline:
1. Intake — structured web form, uploaded PDF of a marked evaluation sheet, or a gallery-uploaded photo.
2. Extraction — OCR and template-based mark detection for PDFs; OpenCV preprocessing (deskewing, adaptive thresholding, perspective correction) plus the same mark-detection logic for photographed sheets; both paths normalize into a single item-level score vector.
3. Knowledge Base — the licensed scoring manual is digitized, chunked into semantically meaningful segments, and embedded via Sentence-BERT into a local ChromaDB vector store; the score vector is used at run time to semantically retrieve relevant manual passages.
4. Interpretation — an LLM receives the retrieved passages and score vector, prompted to ground every substantive statement in a retrieved passage (to reduce hallucination risk).
5. Report Output — scores and generated interpretation are compiled into a structured, downloadable PDF report.

Development process model:
Incremental development — each pipeline layer is implemented, tested, and integrated as a working increment before the next begins, with continuous validation against sample evaluation sheets.

Tools / technology stack (per proposal):
- Backend & AI: Python, FastAPI, LangChain, Sentence-BERT (HuggingFace), ChromaDB, Tesseract OCR / layout-aware OCR, OpenCV, GPT-4o / Claude API
- Frontend & Infrastructure: Next.js / React, PostgreSQL, Docker, Git/GitHub

Scope — included:
- Web-based structured intake form
- PDF upload with OCR/template-based mark extraction
- Gallery image upload with OpenCV preprocessing
- RAG pipeline over one digitized, licensed scoring manual (Sentence-BERT + ChromaDB)
- LLM-based interpretation module generating a manual-cited summary
- Downloadable, structured PDF report as final output

Scope — explicitly NOT included (important — do not claim these):
- Clinical diagnosis, or any claim of replacing a licensed psychologist's judgment (this is a support/interpretation aid only)
- Support for multiple scoring manuals/instruments simultaneously (prototype targets a single licensed instrument)
- Production-scale, multi-tenant clinical deployment, continuous model retraining, or HIPAA/GDPR-grade compliance infrastructure
- A native mobile application (scoped as a responsive web app)
- OCR/handwriting recognition beyond English-language marked forms

Data/ethics note:
Development and testing use synthetic or de-identified sample evaluation sheets, not real patient records — institutional ethical clearance and clinical data-sharing agreements are outside the scope of this BS-level FYP.

Key risks identified (per proposal):
- OCR/mark-detection accuracy on handwritten or low-quality photographed sheets (mitigated via template-based bounding-box detection + manual-correction UI fallback)
- Restricted licensed access to a scoring manual for digitization (mitigated via supervisor/institutional access or an openly available instrument of equivalent structure)
- LLM hallucination during interpretation (mitigated via strict RAG-grounded prompting requiring citation of retrieved passages)
- Timeline slippage across a multi-module pipeline (mitigated via the incremental process model and milestone schedule)

Milestone schedule (FYP-I, 14 weeks):
1. Requirement gathering & literature/manual access — Week 1–2
2. System architecture & database design — Week 3
3. Form intake module development — Week 4–5
4. PDF/Image OCR & CV extraction pipeline — Week 6–7
5. Knowledge base construction (manual digitization & embedding) — Week 8
6. RAG + LLM interpretation module — Week 9–10
7. Report generation & UI integration — Week 11
8. Testing & validation — Week 12
9. Documentation & FYP-I submission — Week 13–14

Target application areas (per proposal):
Special-education schools, pediatric clinics, and early-intervention centers — particularly in under-resourced regions such as Pakistan — plus NGOs running community screening programs and telehealth platforms offering remote developmental assessments.
